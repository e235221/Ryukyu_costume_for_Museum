# 琉球衣装AR体験

## 概要

カメラに映った最大3人に琉球衣装PNGやヤンバルクイナの頭部PNGを重ねるWebアプリ。人物ごとに男性衣装・女性衣装・ヤンバルクイナ・なしを選択できる。背景は「なし・海・石畳・首里城（復元前）・首里城（復元後）」。

## Usage

### ヤンバルクイナへの顔置換

ARを開始し、人物番号を選んで「ヤンバルクイナ」を押す。その人の顔を
`yanbarukuina.png` で覆い、位置・サイズ・傾きに追従する。体と服はカメラ映像のまま。「なし」で元の顔に戻す。琉球衣装とは排他的な選択で、他の人物の設定には影響しない。背景切替も併用可能。

1254×1254 PNG内の頭部範囲 (58,99)〜(1194,1148) を基準に、顔より少し大きめに拡大する。写真の編集や新しい認識モデルの追加は行わず、既存のCanvas 2Dに描画するため負荷増を抑えられる。強い横向き・遮蔽では覆い切れない場合がある。

### 基本操作

1. プロジェクト直下の `ARを起動.command` をダブルクリックする（起動済みなら不要）。
2. `http://127.0.0.1:8000/` を開き、「AR体験を始める」を押してカメラを許可する。
3. 最初に認識した顔に画面左から人物1・2・3の番号が付く。
4. 画面下の人物ボタンを押し、男性の琉装・女性の琉装・ヤンバルクイナ・なしを選ぶ。顔の上にも対応する番号が表示される。
   顔の上の番号は検出後約5秒でフェードアウトする。番号振り直し・再入場時には再表示する。認識人数は右下の操作ボタンのすぐ上に表示する。
5. 人物が交差して番号が入れ替わった場合は、並び直して「番号を左から振り直す」を押す。衣装設定は番号ごとに保持される。
6. 右上の「背景を選ぶ」を開き、なし・海・石畳・首里城（復元前）・首里城（復元後）から選ぶ。なし・海・石畳は1行目、首里城2種類は2行目に表示する。見出しを押すと背景ボタンを開閉できる。左上の矢印でカメラ・認識・背景処理を停止する。
7. 画面上部の「📷 撮影」を押すと、カメラの人物・選択中の背景・人物ごとの衣装／ヤンバルクイナをPNGとして保存する。操作ボタン、人物番号、認識人数、ガイドは保存画像に含まれない。背景の準備中は、完了してから撮影する。
8. 右上のインフォメーションマークを押すと琉装の共通キャプションを表示する。上部の「文字サイズ」バーで本文を80〜160%に変更できる。ヤンバルクイナの解説にも同じ設定を適用する。

ヤンバルクイナ選択中のインフォメーションには、飛べない体への適応、沖縄島北部の固有種であること、1981年の新種発表、捕食・交通事故・森林環境の変化と保全活動について表示する。顔の置き換え操作に関する説明はキャプションへ含めない。

ターミナルから起動する場合（プロジェクト直下）:

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory files
```

ファイルの直接ダブルクリックではなくHTTPのURLを使う。同じMacのlocalhostはHTTPで利用可能。他端末向けの公開はHTTPSが必要。GitHub Pagesなどで公開する際は下記のアプリファイルと画像を一緒に配置する。

### 写真撮影

撮影ボタンはカメラと顔認識の準備完了後に有効になる。背景を選んだ場合は「背景を準備中...」の表示が消えてから撮影する。保存形式はPNGで、ファイル名は `ryukyu-ar-YYYYMMDD-HHMMSS.png`。背景なしでは画面表示と同じ鏡像カメラを使い、背景ありでは切り抜き済みの人物映像と背景を使う。その上に最大3人分の衣装またはヤンバルクイナを重ねる。

保存対象はカメラ映像・背景・衣装だけで、撮影ボタン、衣装選択、人物番号、認識人数、ガイド、メッセージは含めない。ブラウザのダウンロード制限や保存確認が表示された場合は、利用者が保存先を選ぶ。

### 画像を差し替えたのに表示が変わらない場合

`orion_man.png` と `orion_woman.png` は同じファイル名のまま差し替えるため、ブラウザが古い画像を保持する場合がある。AR画面を終了し、Macでは `Command + Shift + R` で強制再読み込みする。それでも変わらない場合はブラウザの当該サイトデータを消すか、画像URLへバージョン値を付ける。

背景候補や撮影処理を更新した際に旧JavaScriptが残らないよう、`background.js` と `multiface.mjs` の読込URLにはバージョン値を付けている。これらのファイルを変更して公開する場合は、`index.html` の `?v=` も更新する。

2026-09-20時点の画像は男性2732×4096、女性1366×2048のRGBA PNGで、背景と顔穴に完全透明画素がある。8000番のサーバーから取得した画像と作業ディレクトリ内の画像のSHA-256一致も確認済み。なお、描画時は683×1024相当へ縮小し、旧画像基準の顔穴座標を使用しているため、差し替え後は顔穴と輪郭の実画面確認が必要。

## 構成

- `index.html`: 画面、人物選択、衣装選択、Markdown形式の共通琉装キャプション
- `multiface.mjs`: カメラ、最大3人の顔認識、衣装描画、割当ボタン
- `face-slots.mjs`: 顔の位置に基づく番号の維持
- `background.js`: 人物の切り抜きと背景合成
- `photo-capture.mjs`: カメラ・背景・衣装レイヤーの撮影用合成
- `orion_man.png` / `orion_woman.png`: 透過衣装
- `yanbarukuina.png`: 顔を覆う透過頭部画像
- `background_beach.jpg` / `background_ishidatami.jpg`: 海・石畳の背景画像
- `background_Shurijo_Castle_before.jpg` / `background_Shurijo_Castle_after.jpg`: 首里城の復元前・復元後の背景画像
- `costume-fit.js`: 旧MindAR版の参考ファイル（現行アプリでは未使用）

## 技術選定理由

- MediaPipe Face Landmarker（tasks-vision 0.10.9）: `numFaces: 3` で複数の顔のランドマークを直接取得できるため、1人前提のMindAR連携から置き換えた。
- Canvas 2D: 透過PNGの移動・拡大縮小・回転を人物ごとに描けるため。A-Frameと3D描画への依存を除き、写真の顔ハメに必要な処理に絞った。
- 撮影用Canvas合成: DOM画面全体を撮影せず、カメラ／背景と衣装レイヤーだけを再合成できるため。操作UIを保存画像から確実に除外できる。
- Selfie Segmentation 0.1.1675465747: 背景を変えるときだけ軽量な人物切り抜きを追加できる。
- ビルド不要のJavaScript: 静的サーバーで運用できるため。

## 配置と負荷

顔の頬・額・顎と両目から画像の位置・大きさ・傾きを計算する。琉球衣装は683:1024、ヤンバルクイナは1:1の縦横比を維持。男性の顔穴は (306,189)〜(371,268)、女性は (313,239)〜(375,315)。画像を変更する場合は `multiface.mjs` 内の顔穴・頭部座標も更新する。旧3D版の調整スライダーは使用しない。

撮影は1280×720・24fpsを目安に要求し、顔検出は最大約12.5fps、背景切り抜きは最大10fps。実際の速度・撮影解像度は端末による。GPU初期化に失敗した場合はCPUを試す。モデルとライブラリはCDNから読み込み、映像の認識処理は端末内で行う。

## 制約

- 人物番号は顔認証ではなく位置の対応付け。認識結果の順序変化には対応するが、交差・遮蔽・長い離席では番号が入れ替わる可能性がある。約0.9秒の未検出後に番号の追跡枠を解放する。
- 4人以上映る場合、検出される最大3人を処理する。
- 遠距離の小さい顔や横顔は認識しにくい。2D画像なので体の動きに沿った衣服の変形は行わない。
- 「なし」でも人物の番号と追跡は維持する。

## 動作確認状況（2026-09-20更新）

- ユーザーから「人物別の動作確認はクリアしました」と報告を受けた。人物別機能はユーザー確認済みとして扱う。実際の同時人数・ブラウザ・端末・連続運転時間は報告されていないため、3人同時・全ブラウザ・長時間安定動作まで確認済みとはしない。
- 旧1人版はエージェントがChrome実カメラで男女衣装の表示・顔穴透過・切替を確認した。
- 現行版は割当・追跡・ヤンバルクイナ描画計算・背景処理の模擬テストがPASS。エージェントによる現行版の実機検証はChrome拡張機能UIに阻まれた。
- 背景合成の実画面、長時間性能、Safariでの現行版動作については独立した確認結果がまだない。
- 写真撮影は鏡像、背景利用、衣装の重なり順、日時付きファイル名の自動テストがPASS。8000番で撮影UIとモジュールが配信されることも確認済み。実カメラからのダウンロードとSafari／Chrome双方の保存結果は未確認。

## 残る問題点と改善候補

以下はコード確認に基づく制約・潜在的問題。今回再現した不具合という意味ではない。

| 優先度 | 問題点・根拠 | 改善候補 |
|---|---|---|
| 高 | 人物の交差・遮蔽・再入場で番号と衣装が入れ替わり得る。位置で対応付けし、約0.9秒で枠を解放する（face-slots.mjs）。 | 立ち位置を指定し、番号振り直しを案内する。必要なら再入場時の割当確認を追加する。 |
| 高 | 顔追跡と背景合成が別周期・別フレームで動く。背景変更中の速い動きでは人物映像と衣装の位置がずれる可能性（multiface.mjs / background.js）。 | 同じ入力フレームに対する顔結果・背景結果をそろえて合成する。 |
| 中 | 顔検出はメインスレッドで同期実行し、背景切り抜きも並行稼働する。3人＋背景変更時の応答遅延・発熱・長時間性能は未測定。 | 実機で連続運転とフレーム時間を測定し、必要ならWorkerへの移動や解像度・推論頻度の調整を行う。 |
| 中 | 遠距離・横顔・手で隠れた顔では認識が切れやすい。描画は2Dで、体のポーズ・前後の遮蔽には合わせていない。 | 全身体験を重視する場合は姿勢推定または固定式顔ハメを検討する。 |
| 中 | CDN・モデル配信元への接続が必要。背景のmodel.sendにはタイムアウトがなく、処理が応答しなければbusyのまま再開できない可能性。顔モデル初期化の未完了Promiseも再試行で共有される。 | 展示用に依存資産を固定配置し、モデル初期化・推論のタイムアウトと再生成処理を追加する。 |
| 低 | 人物番号は5秒で消え、人物を選び直しても顔上には再表示しない。人数が多いと割当対象を見失う可能性。 | 人物ボタンを押した際だけ対象番号を一時再表示する。 |

次の確認では、複数人が交差・離席する操作、背景ありでの速い動き、30分程度の連続利用を優先する。

## 検証

プロジェクト直下で実行:

```sh
node files/check-multiface.mjs
node files/check-assignments.mjs
node files/check-background.cjs
node files/check-photo-capture.mjs
node files/check-caption.cjs
```

3人の割当・検出順序の変更・一時消失・再入場・独立した衣装ボタン・背景切替と停止・撮影時のレイヤー順と鏡像・男女共通キャプションのMarkdown表示を検査する。顔入力、DOM、背景モデルはテスト用の模擬値であり、実カメラの精度・描画・性能を検証するものではない。
